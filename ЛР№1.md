#### Тема: "Знайомство з робочим середовищем віртуальних машин та особливостями операційної системи Linux".
#### Мета роботи: 
1. Знайомство з гіпервізорами різного типу, віртуалізацією при роботі з операційними системами.
2. Знайомство з основними видами сучасних ОС, короткий огляд їх можливостей.

Завдання для попередньої підготовки.
##### Словник термінів: 
1. VirtualBox - безкоштовний гіпервізор типу 2 від компанії Oracle для створення та запуску віртуальних машин.
2. Ядро (Kernel) - основна частина операційної системи, яка безпосередньо взаємодіє з апаратним забезпеченням комп’ютера.
3. Dual Boot - спосіб встановлення двох (або більше) операційних систем на один комп’ютер з можливістю вибору при завантаженні.
4. CLI (Command Line Interface) - інтерфейс командного рядка. Робота з системою відбувається шляхом введення текстових команд.
5. GUI (Graphical User Interface) - графічний інтерфейс користувача. Робота відбувається за допомогою вікон, меню, іконок і миші.
6. GNU GPL (General Public License) - ліцензія вільного програмного забезпечення, яка гарантує користувачам свободу запускати, вивчати, змінювати і поширювати програму.
7. JWM (Joe’s Window Manager) - дуже легкий віконний менеджер з мінімальним споживанням ресурсів.

#### 2.1  Гіпервізор (hypervisor) — це спеціальне програмне забезпечення, яке дозволяє створювати та запускати віртуальні машини. Він розподіляє ресурси фізичного комп’ютера (процесор, пам’ять, диски, мережу) між кількома ізольованими гостьовими операційними системами.
##### Існує два основних типи гіпервізорів
- Тип 1 (Bare-metal, "голе залізо")
Встановлюється безпосередньо на апаратне забезпечення комп’ютера, без участі хостової операційної системи. Має вищу продуктивність і використовується переважно на серверах.
Приклади: VMware ESXi, Microsoft Hyper-V, Xen, KVM.
- Тип 2 (Hosted)
Працює як звичайна програма поверх уже встановленої операційної системи (Windows, Linux, macOS). Простіший у використанні, але має трохи нижчу продуктивність через додатковий шар.
Приклади: Oracle VirtualBox, VMware Workstation, Parallels Desktop.
#### 2.2 Основні компоненти та можливості гіпервізора VirtualBox.
##### Основні компоненти VirtualBox:
- Гіпервізор VirtualBox - ядро системи віртуалізації.
- VirtualBox Manager - графічна оболонка для створення та керування віртуальними машинами.
- Guest Additions - спеціальні драйвери та утиліти, які встановлюються всередині гостьової ОС для покращення інтеграції.
- Віртуальне апаратне забезпечення - емуляція процесора, оперативної пам’яті, жорстких дисків (VDI, VMDK, VHD), мережевих адаптерів, звукових і USB-пристроїв.
- Система знімків (Snapshots) - можливість зберігати стан віртуальної машини і швидко повертатися до нього.
- Shared Folders - спільні папки між хостом і гостьовою системою.
##### Основні можливості VirtualBox:
- Створення та запуск віртуальних машин з різними операційними системами (Windows, Linux, macOS, тощо).
- Підтримка 32- та 64-бітних гостьових систем.
- Динамічні та фіксовані віртуальні диски.
- Підтримка USB-пристроїв, веб-камер, принтерів.
- Знімки стану (snapshots) і клонування віртуальних машин.
- Віддалений доступ до віртуальних машин (VRDP).
- Кросплатформенність (працює на Windows, Linux, macOS).
  #### Відповіді на питання:
#### 2.1 Етапи розгортання операційної системи на базі віртуальної машини VirtualBox.
1. Встановити Oracle VirtualBox на хост-систему.
2. Завантажити образ дистрибутиву Linux (ISO-файл).
3. Створити нову віртуальну машину:
- вказати назву, тип ОС (Linux) і версію
- виділити обсяг оперативної пам’яті
- створити віртуальний жорсткий диск
4. Запустити віртуальну машину і пройти стандартний процес встановлення ОС.
5. Перезавантажити ВМ і перевірити роботу.
#### 2.2 Апаратні обмеження при встановленні 32- та 64-бітних ОС.
##### 1. 32-бітна ОС
- Може працювати на 32-бітному та 64-бітному процесорі.
- Обмеження оперативної пам’яті - зазвичай до 4 ГБ.
- Не може використовувати всі можливості сучасних 64-бітних процесорів.
##### 2. 64-бітна ОС:
- Вимагає 64-бітний процесор з підтримкою відповідних інструкцій.
- Може адресувати значно більше оперативної пам’яті.
- На 32-бітному процесорі не встановиться.
#### 2.3 Основні етапи встановлення OS Linux у текстовому режимі.
1. Завантаження з інсталяційного носія (ISO/USB).
2. Вибір мови та розкладки клавіатури.
3. Розмітка диска (створення розділів: /, /home, swap тощо) — вручну або автоматично.
4. Вибір пакетів / мінімальної системи.
5. Встановлення базової системи.
6. Налаштування завантажувача (GRUB).
7. Створення користувача та пароля root.
8. Завершення встановлення і перезавантаження.
#### 2.4 Як доустановити графічні оболонки GNOME та KDE, якщо система вже встановлена в текстовому режимі.
- Для Ubuntu та Debian-подібних систем спочатку оновлюють список пакетів командою (sudo apt update). Після цього для встановлення GNOME використовують команду (sudo apt install ubuntu-gnome-desktop). Для встановлення KDE Plasma виконують (sudo apt install kubuntu-desktop) або (sudo apt install plasma-desktop sddm).
- У системах на базі Fedora використовують команди (sudo dnf groupinstall "GNOME Desktop Environment") та (sudo dnf groupinstall "KDE Plasma Workspaces").
- Після встановлення оболонок систему переводять у графічний режим командою (sudo systemctl set-default graphical.target) і перезавантажують. На екрані входу можна буде вибрати потрібне середовище (GNOME або KDE).
#### 2.5 Коротка характеристика графічних інтерфейсів.
##### GNOME 

Сучасне, мінімалістичне та зручне середовище робочого столу. Акцент зроблено на простоті використання та чистому інтерфейсі. Використовує Activities Overview, підтримує розширення (extensions). Споживає середню кількість ресурсів. Підходить для користувачів, які цінують сучасний вигляд і зручність без зайвих елементів.

##### JWM (Joe’s Window Manager)

Дуже легкий і швидкий віконний менеджер. Майже не споживає оперативної пам’яті та процесорних ресурсів. Має простий вигляд (панель задач, меню), налаштовується через один XML-файл. Часто використовується на слабких комп’ютерах. Ідеальний вибір коли потрібна продуктивність і мінімум "надлишків".
 #### Контрольні питання:
##### 1. Порівняйте гіпервізори типу 1 та типу 2.
- Гіпервізори типу 1 (bare-metal) встановлюються безпосередньо на апаратне забезпечення і працюють без хостової ОС. Вони мають вищу продуктивність і використовуються переважно на серверах та в хмарних системах (VMware ESXi, Hyper-V, Xen, KVM).
- Гіпервізори типу 2 (hosted) працюють як звичайні програми поверх уже встановленої операційної системи. Вони простіші у використанні, але менш продуктивні. Застосовуються на персональних комп’ютерах для навчання та тестування (VirtualBox, VMware Workstation).
- Основна відмінність - тип 1 працює напряму з "залізом", а тип 2 - через хостову ОС.
##### 2. GNU GPL.
GNU General Public License - ліцензія вільного програмного забезпечення. Основна концепція: користувач отримує свободу запускати, вивчати, змінювати та поширювати програму, але зобов’язаний зберігати ці самі свободи для всіх наступних користувачів (copyleft).
##### 3. Суть програмного забезпечення з відкритим кодом.
Відкритий код (Open Source) означає, що вихідний код програми доступний для перегляду, вивчення, зміни та поширення. Це дозволяє спільноті покращувати програмне забезпечення, шукати вразливості та створювати власні модифікації.
##### 4. Що таке дистрибутив?
Дистрибутив Linux - це збірка ядра Linux, системних утиліт, графічного середовища, набору програм, системи управління пакетами яка підготовлена для зручного встановлення та використання (Ubuntu, Fedora, Debian тощо).
##### 5. Задачі системного адміністрування на базі ОС Linux.
- управління користувачами та правами доступу
- налаштування мережі та міжмережевих екранів
- моніторинг системи та логування
- управління службами (systemd)
- резервне копіювання
- встановлення та оновлення програмного забезпечення
- налаштування веб-серверів, баз даних, віртуалізації тощо
##### 6. Як пов’язані Android та Linux?
Android побудований на модифікованому ядрі Linux. Він використовує ядро Linux, але має власну бібліотеку (Bionic), власну систему ініціалізації та повністю інший користувацький простір. Тому Android - це окрема ОС на базі ядра Linux, а не класичний дистрибутив GNU/Linux.
##### 7. Основні можливості та сфера використання Embedded Linux.
Embedded Linux використовується у вбудованих системах: маршрутизатори, телевізори, промислове обладнання. Переваги: малий розмір, гнучкість, стабільність, відсутність ліцензійних відрахувань.
##### 8. Яким чином можна змінити тип завантаження Linux: у текстовому режимі (рівень 3) або графічному (рівень 5)? Чим відрізняються режими CLI та GUI?
У сучасних дистрибутивах Linux для зміни режиму завантаження використовують систему systemd. Щоб система завантажувалася в текстовому режимі (аналог рівня 3), виконують команду:
- sudo systemctl set-default multi-user.target

Для завантаження в графічному режимі (аналог рівня 5) використовують:
- sudo systemctl set-default graphical.target

Щоб змінити режим без перезавантаження, застосовують команди:
- sudo systemctl isolate multi-user.target - перехід у текстовий режим
- sudo systemctl isolate graphical.target - перехід у графічний режим
##### Відмінність режимів CLI та GUI: 
- CLI (Command Line Interface) — робота відбувається виключно через командний рядок. Цей режим споживає мінімум ресурсів, забезпечує високу швидкість і повний контроль над системою.
- GUI (Graphical User Interface) — робота відбувається за допомогою графічного інтерфейсу (вікна, меню, іконки, миша). Він зручніший для більшості користувачів, але потребує більше оперативної пам’яті та ресурсів процесора.
